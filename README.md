# BCA Trajectory Prediction and Decoder

This project predicts centroid trajectories, decodes predicted centroid behavior, flags behavioral anomalies, and exposes the results in a Streamlit trajectory dashboard.

The prediction pipeline must be run before opening the dashboard. The dashboard reads the CSV outputs generated by `app.py`.

## Installation

From the project root, create and activate a Python environment, then install the project requirements:

```bash
python -m venv .venv
```

Install dependencies:

```bash
pip install -r requirements.txt
```

The dashboard is a Streamlit app. If Streamlit is not already installed by your environment, install it before launching the dashboard:

```bash
pip install streamlit
```

## Project Data Layout

Place each project's input data under `projects/<project_name>`.

The project folder must contain the clustered/user embedding data and centroid embeddings used by the pipeline. `app.py` loads weekly centroid parquet files from:

```text
projects/
  sample_project/
    cluster_embeddings/
      centroids_with_usage_labels/
        <weekly centroid parquet files>
```

Use the same `<project_name>` value when running both `app.py` and the dashboard configuration.

## Running the Prediction Pipeline

Run all commands from the project root.

The required CLI argument is `--mode`. Modes can be combined:

- `0`: End-to-end run. Internally expands to modes `1 2 3 4 5`.
- `1`: Kalman Filter trajectory prediction.
- `2`: Multi-lag Drift trajectory prediction.
- `3`: Polynomial Regression trajectory prediction.
- `4`: Behavioral decoder and anomaly detection.
- `5`: Trajectory and anomaly visualization outputs.

### End-to-End Run With Defaults

Run the project end to end with default parameters and all prediction approaches:

```bash
python app.py --project_name sample_project --mode 0
```

### End-to-End Run With Known-Week Forecasting

Run the project end to end with default parameters and all approaches, while forecasting known weeks so predictions can be compared with actual results:

```bash
python app.py --project_name sample_project --mode 0 --forecast_n_known_weeks 24
```

### Selected Modes and Hyperparameters

Run selected stages and override approach-specific hyperparameters:

```bash
python app.py --project_name sample_project --mode 1 2 4 5 --lag 24 --forecast_n_known_weeks 24
```

This command runs:

- mode `1`: Kalman Filter prediction
- mode `2`: Multi-lag Drift prediction using `--lag 24`
- mode `4`: Behavioral decoder and anomaly detection
- mode `5`: Visualization outputs

## Pipeline Outputs

`app.py` writes prediction, decoder, anomaly, and visualization outputs under:

```text
projects/<project_name>/centroid_trajectory_predictions/
```

The Streamlit dashboard expects the decoder and anomaly CSV outputs generated by modes `4` and `5`, including files under:

```text
projects/<project_name>/centroid_trajectory_predictions/
  behavioral_decoder/decoded_centroids/<model_name>/
  flagged_decoded_centroids/<model_name>/
```

Because these files are produced by the pipeline, always run `app.py` successfully before launching the dashboard.

## Running the Trajectory Dashboard

After `app.py` finishes, set the dashboard project/model configurations in:

```text
src/trajectory_dashboard/config.py
```

Then launch the Streamlit dashboard from the project root:

```bash
streamlit run src/trajectory_dashboard/Trajectory_Overview.py
```

Open the local Streamlit URL shown in the terminal to review trajectory predictions, decoded behavior, and anomaly analysis.


## Neural-Prediction-Assisted Anomaly Detection

The separate `src/anomaly/` pipeline supports an optional third signal derived from the existing `src/neural_prediction/` model: the one-step-ahead prediction residual. The original motion-based and Isolation Forest signals remain active whether or not neural scoring is enabled.

### Run Without Neural Prediction

The original validation flow remains available:

```bash
python scripts/validate_anomaly_real_data.py --project-name trajectory_prediction_data_hitachi
```

### Run With a Trained Neural Checkpoint

First train a neural prediction model using the same project, PCA dimensionality, train/validation split, and preprocessing settings used for anomaly validation. The checkpoint must predict the same `z_` coordinate system that the validation script creates.

Then run, for example:

```bash
python scripts/validate_anomaly_real_data.py \
  --project-name trajectory_prediction_data_hitachi \
  --neural-checkpoint projects/trajectory_prediction_data_hitachi/neural_models/hybrid_cnn_lstm_attention_best.pth \
  --neural-device cpu
```

Use the checkpoint filename actually produced by your training run. `--neural-device cuda` can be used when CUDA is available.

When a checkpoint is supplied:

1. The motion detector and Isolation Forest are fitted on the chronological training split.
2. Neural one-step-ahead errors are calculated on the held-out validation split, using only earlier training observations as history.
3. Validation residuals calibrate the neural percentile ranks and fused warning/high thresholds.
4. Test observations are scored using training + validation history; target observations are only appended to history after their own prediction is made.
5. The CSV output includes `neural_prediction_error` and `neural_rank` at timestep and window levels, and the JSON report records whether neural scoring was enabled.

Rows without enough historical observations for the checkpoint's lookback receive no neural residual. In that case, the neural rank is neutral and the existing motion/Isolation Forest signals still contribute. Scores are anomaly rankings, not probabilities; review flagged trajectories before treating them as confirmed anomalies.

The fitted pipeline artifact format was bumped to version 2 for the expanded scoring state. Regenerate older anomaly artifacts using this branch before loading them with the updated code.
